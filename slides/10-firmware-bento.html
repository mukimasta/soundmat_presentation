Main loop
loop() { scan_sensors(); // drive ring HIGH, sweep two muxes, ADC × 256 send_sensor_data(); // S frame → Pi receive_led_data(); // L frame ← Pi (non-blocking) update_leds(); // WS2812B via RMT }
No threads. No acks. No retries. A scan finishes, the frame ships. The Pi answers when it can; the buffer is sipped at the top of each tick. A bad checksum just drops — environmental music never notices a missing frame.
ESP32 → Pi
S frame · 256 raw ADC reads
S:4095,4093,4090,2031,…,3498*A7\n
ASCII, comma-separated, XOR-checksum. Inner rings ship 32 values too — the Pi folds them down. Tail it in any serial monitor.
Pi → ESP32
L frame · 108 RGB triplets
L:000000,0A0500,1A0F00,…,000000*3E\n
Same envelope, hex payload. No L frame this tick? Repeat the last buffer. The light always has something to do.
